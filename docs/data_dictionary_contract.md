# NL2EventLog Data Dictionary — Common Contract (v1)

The **canonical logical contract** across datasets is:

```text
dictionary_schema_version
name / dataset_id / language / dbms / timezone
documentation_sources
tables[]:
  table, metadata_id, definition, documentation_url, source_schema
  row_grain, primary_key, foreign_keys
  columns[]:
    metadata_id, name, sql_type, source_type
    definition, definition_source, source_references
    required, primary_key_position, foreign_keys
    temporal_role, unit
```

**Evidence and null policy.** A definition describes the field's meaning, not its Gold Event Candidate or its case membership. `null` signifies unavailable or unverified evidence. Any model-created interpretation must be separate and explicitly attributed, never silently copied into a source-derived definition. Source documentation URLs are specific to the relevant table or column whenever possible.

**Different physical and original types.** `sql_type` reports the actual SQLite representation; `source_type` reports the upstream native type when verified. A MIMIC-IV field imported as SQLite `TEXT` may still have upstream type `TIMESTAMP` or `INTEGER`. Do not falsify SQLite typing to match clinical source typing.

**Relationships.** Only physically declared SQL foreign keys belong in the declared-FK field. Candidate links inferred from matching fields or official documentation are represented separately as such, with provenance and verification status. Object/Event Gold, case notions and extraction specifications are not included.

**Compatibility and rollout.** Existing dictionaries use two legacy shapes (`tables` as a map in MIMIC vs as an array in AdventureWorks/HospitalFlow/etc.), plus `definition` vs `description` and `type` vs `sql_type`. `tools/normalize_data_dictionaries.py` projects each to `docs/data_dictionary.standard.json`, leaving the original `input/data_dictionary.json` untouched to avoid breaking the current NL2EventLog loaders. Standardized projections for other datasets can be generated by running the tool in the repository. The unified shape is a *view*, not a destructive migration.

**MIMIC source provenance:** [Official MIMIC-IV documentation](https://mimic.mit.edu/docs/iv/), [hospital module](https://mimic.mit.edu/docs/iv/modules/hosp/), [ICU module](https://mimic.mit.edu/docs/iv/modules/icu/), and [MIMIC-IV Demo 2.2](https://physionet.org/content/mimic-iv-demo/2.2/). The official table pages supply source descriptions and native types, not the synthetic HospitalFlow document.
